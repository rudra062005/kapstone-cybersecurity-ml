2. REAL-LIFE PROBLEM KYA THA? (WHY DID WE BUILD THIS?)
--------------------------------------------------------------------------------
Ek badi company ke network me roz karodo logs aate hain (har ek click, packet,
login ka hisaab). 
Agar koi human analyst baith kar har log ko check karega toh:
1. Wo thak jayega (Alert Fatigue).
2. Asli attack miss ho jayega.
3. Alag-alag alerts ko aapas me relate karna bohot mushkil hota hai.

Humne is problem ko solve karne ke liye 5-layer pipeline banayi hai:
Log Aaya -> Model ne check kiya -> Alert Correlate hua -> Compliance Rule laga
-> Manager ke Dashboard par report aayi.

--------------------------------------------------------------------------------
3. PURA ARCHITECTURE - 5 STEP STORY (Bache ko samjhane jaisa)
--------------------------------------------------------------------------------

STEP 1: DATA CONNECTORS (Gate Ka Chaukidar)
- File: src/connectors.py
- Kaam: Bahar se alag-alag tarah ke security data ko andar lana.
  1. CsvLogConnector: Network flow logs (CSV format) ko chunk-by-chunk stream karta hai.
  2. ThreatIntelConnector: Jaise police ke paas 'wanted criminals' ki list hoti hai,
     waise hi ye connector malicious IPs aur unke MITRE ATT&CK tactics (jaise Initial
     Access, Reconnaissance) ka record check karta hai.
  3. AssessmentFindingConnector: Vulnerability scanner (jaise Nessus/OpenVAS) ke JSON
     findings ko system me lata hai.

STEP 2: PREPROCESSING (Kachra Saaf Karna & Format Banana)
- File: src/preprocessing.py
- Kaam: Raw log data machine learning model ke samajhne layak nahi hota.
  1. Humne 39 numeric features (packet rate, bytes, TTL, etc.) ko median se impute
     kiya aur scale kiya (StandardScaler).
  2. 3 categorical features (proto, service, state) ko OrdinalEncoder se encode kiya.
  3. Data Leakage Rokna: Humne 'id', 'label', aur 'attack_cat' columns ko model se
     hata diya taaki model cheating na kare.

STEP 3: MACHINE LEARNING ENGINE (The Brain / Intelligence)
- File: src/train_model.py
- Model: Random Forest Classifier (100 decision trees)
- Kaam: Har network packet ko dekhkar probability nikalta hai (0.0 se 1.0) ki ye
  normal traffic hai ya hacker ka attack.
- Class Weight: Attack traffic ~68% tha aur normal ~32%, toh humne 'balanced' class
  weights use kiye taaki model kisi ek taraf biased na ho.

STEP 4: ALERT CORRELATION (Dots Ko Connect Karna)
- File: src/correlation.py
- Kaam: Ek single alert hacker ka full attack nahi hota. Hacker pehle scan karta hai,
  fir port dhoondhta hai, fir exploit bhejta hai.
  Humara correlator alerts ko factors ke basis par group karta hai:
  - Same Source IP (ek hi hacker alag-alag jagah hamla kar raha hai)
  - Same Target Asset (ek hi server pe baar baar hamla ho raha hai)
  - Time window (paas paas ke time me attacks)
- Sath me human-readable 'Correlation Reasoning' generate karta hai:
  "Correlated 5 alerts sharing source IP 175.45.176.1 targeting Server-Web-01".

STEP 5: COMPLIANCE MAPPING (Rule Book Check Karna)
- File: src/compliance.py & src/compliance_mappings.json
- Kaam: Cybersecurity me rules hote hain (NIST CSF 2.0 aur ISO/IEC 27001:2022).
  Jab koi attack pakda jata hai, hum batate hain:
  - DoS Attack hua? -> NIST Control PR.DS-4 & ISO A.8.6 (Capacity Management).
    Remediation: Rate limiting lagao, upstream scrubbing karo.
  - Reconnaissance (Scanning) hua? -> NIST DE.AE-1 & ISO A.8.16 (Monitoring).
    Remediation: Scanning IP ko block karo, firewall tight karo.
  - Exploits/Backdoor hua? -> NIST RS.MI-1 & ISO A.8.8 / A.5.26 (Containment).
    Remediation: Machine ko isolate karo, password badlo, patch lagao.

STEP 6: REPORTING, API & DASHBOARD
- File: src/reporting.py, api.py, dashboard.py
- FastAPI (api.py): REST API endpoints (/health, /metrics, /analyze, /incidents, /connectors).
- Streamlit (dashboard.py): 7-page ka visual dashboard jisme interactive charts,
  model metrics, threat table, expandable incidents, aur report download buttons hain.

--------------------------------------------------------------------------------
5. ML METRICS - EXACT REAL NUMBERS (Ratta Maar Lo)
--------------------------------------------------------------------------------
Interviewer metrics zaroor puchega. Real test set metrics:

1. Accuracy: 89.25% (Dummy baseline 55.06% thi, humne +34% improve kiya).
2. Recall: 97.67% (Sabse important metric!).
   - Iska matlab: 45,332 attacks me se model ne 44,274 attacks pakad liye!
   - Miss kitne hue? Sirf 1,058 (False Negative Rate = 2.33%).
3. Precision: 85.03% (Jab model attack bolta hai, toh 85% time wo sahi hota hai).
4. F1-Score: 90.91% (Precision aur Recall ka balanced harmonic mean).
5. False Positive Rate: 21.07% (Normal traffic pe shaq hona. Isko hum SOC me
   threshold slider se control karte hain).

Top 3 Features jo model sabse zyada dekhta hai:
1. ct_state_ttl (13.5%): Connection state aur TTL values ka count.
2. sload (7.5%): Source bits per second (traffic volume spike).
3. sttl (7.0%): Time to live value (OS level anomaly).

6. TOP INTERVIEW QUESTIONS & UNKE SMART JAWAB
--------------------------------------------------------------------------------

Q1: "Random Forest hi kyu use kiya? Deep Learning (Neural Network) kyu nahi?"
Jawab:
"Sir, cybersecurity network flow data tabular format me hota hai. Tabular data
par tree-based models jaise Random Forest aur XGBoost neural networks se behtar
perform karte hain. Random Forest outliers ke khilaf robust hai, feature
importance deta hai, predict_proba se accurate confidence scores nikalta hai,
aur inference speed bohot fast hai (< 0.2 ms per packet), jo real-time SOC me
bohot zaroori hai."

Q2: "Recall 97.67% hai lekin Precision 85% hai. Cybersecurity me kaunsa zyada zaroori hai?"
Jawab:
"Sir, cybersecurity me Recall sabse critical hota hai. Kyuki agar False Negative
hua (hacker attack hua aur humne miss kar diya), toh company ka data leak ya
ransomware encryption ho sakta hai. Agar False Positive hua (normal packet pe shaq),
toh analyst bas 1 minute check karega, par data safe rahega. Isliye humne high
recall ko prioritize kiya hai."

Q3: "Task 4 Data Connectors me kya implement kiya?"
Jawab:
"Sir, maine modular BaseDataConnector class design ki hai jisme teen concrete
connectors hain:
1. CsvLogConnector jo batching aur streaming chunking support karta hai.
2. ThreatIntelConnector jo real-time IP reputation lookup aur MITRE ATT&CK tactic
   mapping karta hai.
3. AssessmentFindingConnector jo vulnerability scan results (CVEs) ko normalize
   karke pipeline me daalta hai.
Ye teeno FastAPI endpoints (/connectors/ingest) aur Streamlit UI dono me integrated hain."

Q4: "Alert Correlation kaise kaam karta hai?"
Jawab:
"Sir, raw logs me lakho single alerts aate hain. Humara correlation engine unko
three factors par cluster karta hai: Source IP, Target Asset, aur Attack Type
within a temporal window. Clustered alerts ko ek single 'Security Incident'
banaya jata hai jisme aggregate risk score, blast radius, aur correlation
reasoning hoti hai jaise: 'Correlated 5 DoS alerts targeting Server-01 within 300s'."

Q5: "Project ki limitations kya hain?" (Honest limitation batana high maturity dikhata hai)
Jawab:
"Sir, do main limitations hain:
1. Kaggle UNSW-NB15 split me researchers ne raw IP addresses aur timestamps ko
   anonymize/remove kar diya tha taaki model lab subnet memorize na kare. Humne
   is limitation ko document kiya hai aur synthetic mapping di hai.
2. 21% False Positive rate hai, jisko live deployment me whitelist rules aur
   retraining ke zariye further reduce kiya ja sakta hai."
